## Features

- Three outcomes on every tool call, checked before it runs: allow when the action is in budget and on task, deny when it is over or looping, and escalate to the human when it needs a decision.
- Rate limits rather than only totals: dollars per minute per agent and across a fleet, new agents per minute to catch an orchestrator spawning orchestrators, and errors per minute to catch a retry storm behind a provider rate limit.
- Capability checks that fire on a full budget, because the expensive mistakes are cheap commands. Piping the internet into a shell is refused outright; deleting a tree, rewriting git history, reading credentials, publishing or deploying stop and ask.
- Hash-chained receipts naming the human the agent acted for, the tool it tried, the model that answered and the rule that decided. Editing or deleting one record breaks the chain visibly.
- Model-fit advice that reads the task the agent was actually given and says when a top-tier model is doing mechanical work, or a light one is doing work that needs reasoning. It stays quiet when the signal is unclear.
- Spend caps priced as cost-weighted effective tokens, so a cached session that re-reads its context every turn is measured by what it costs rather than by raw token counts.

## Two routes

The hook is the stronger of the two, because a refused action never executes at all and it catches actions that cost nothing. For clients without hook support, the same governor runs as a local proxy: point `OPENAI_BASE_URL` or `ANTHROPIC_BASE_URL` at `http://localhost:4000` and requests are metered and refused with HTTP 429 once an agent is over budget.

## Limits worth knowing

Capability rules are pattern-based and are a guard rather than a sandbox. Only Claude Code has the hook wired today; everything else goes through the proxy. The public ChatGPT website cannot be governed, though anything on the OpenAI API can. It does not detect hallucination and makes no such claim.
